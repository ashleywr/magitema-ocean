# Magitema Ocean

Original Minecraft 1.21.1 / NeoForge 21.1.262 world-generation prototype for Ashley's Magitema pack. It provides named `minecraft:overworld` presets, expanded depth, an ocean-only marine biome source, guarded dry caves, renewable kelp, sparse buried salvage rooms and a one-time shared spawn platform. It is not a formally source-isolated clean-room implementation; the prior research handoff is retained outside this repository.

The source project is in `repo/`. Build with Java 21 using `gradlew.bat clean build`. The runtime mod is `build/libs/magitema-ocean-1.21.1-0.1.0.jar`; `build/distributions/magitema-ocean-data-0.1.0.zip` contains its datapack resources. The companion mod supplies the custom density, biome, structure and worldgen hooks, so the data ZIP alone cannot create these worlds.

## Maginautica test instance

The separate Prism profile `Maginautica` is an isolated copy of the Magitema 1.21.1 / NeoForge 21.1.262 gameplay stack, KubeJS data, configs and visual packs, with 28 terrain or continental structure mods omitted. Its save directory starts empty. The removal list and reason for each JAR are in the wrapper's `private/maginautica-mod-manifest.csv`.

The wrapper's `private/maginautica-instance.json` is a machine-local setup report. The Magitema Prism instance, active Prism worlds and Magitema/Crafty server are not deployment targets for this prototype.

## Make a new world

In Maginautica, select **Create New World** and choose **Magitema Ocean — Oceanblock** or **Magitema Ocean — Exploration** in the world-type/preset selector before creating it. In a dedicated server, install the mod in `mods/` before the first world is created and set `level-type=magitema_ocean:oceanblock` (or `magitema_ocean:exploration`) in `server.properties`. Restart and create a fresh save. Changing a save's level type or installing the mod after creation does not change its generator.

Both presets generate the real `minecraft:overworld`, with minimum Y `-704`, height `1024`, exclusive upper bound `320`, and sea-level reference `63`. Nether and End dimensions use their normal definitions. A save-root `magitema_ocean-settings.sha256` locks the effective generation data, preset profile and seed; a changed fingerprint stops the server with a new-world instruction.

Oceanblock keeps land peaks below water, limits regular ore generation, suppresses injected carvers and runs only the profile's approved structure and placed-feature tags. Exploration adds isolated islands classified as sandy atolls, humid jungle, exposed cliffs or volcanic summits, deterministic ore veins located by burial depth, and more frequent buried salvage rooms. Both profiles share the same geography and protected-cave implementation. Profile choices are fixed at world creation.

Both presets load ten distinct marine biomes, four Exploration island biomes and the existing stone and living cave biomes; only the Exploration floor field can expose island terrain. Marine surface biomes are selected from the same seeded floor field as terrain: floor below Y −485 is hadal trench; −485 to −385 abyssal basin; deeper than −385 on steep relief becomes volcanic flank or, on the higher ridge band, basalt ridge; intermediate rocky floors divide into seamount slope and rocky seabed by local slope; shallower than −155 uses shallow rules, assigning warm flat sites to coral garden, bowl-shaped sites to sheltered lagoon, humid sites to kelp grove, and the rest to sand shelf. Exploration classifies land above Y 63 from local relief and climate; the four island classes use sandy, grass/dirt, exposed stone and basalt surfaces. Sparse jungle trees/ground cover and atoll scrub are opt-in Exploration features. Island decoration performs one deterministic 3×3 biome scan per chunk and runs the registered placed features with their normal placement modifiers. A dedicated-server run on seed `3141592690` found all four classes; saved full chunks confirmed their respective surface blocks and generated island vegetation. See `../tests/maginautica-exploration-island-placement-3141592690.json`. Cave biomes begin more than 48 blocks below the analytical floor. Ridge/flank seabeds receive basalt; shelf, reef and lagoon floors receive sand; other marine floors retain gravel sediment. Kelp grove uses denser, taller kelp columns than the scattered kelp allowed on shelves, lagoons and reefs. Coral garden adds vanilla warm-ocean coral and sea-pickle features; hadal trench, basalt ridge and volcanic slope can receive NauTec vent-field and tubeworm features. Feature tags such as `oceanblock_hadal_trench` and `exploration_coral_garden` scope selected placed features to a biome, while the profile tag remains the allowlist. Add a modded placed feature to both its profile allowlist and a biome-scoped tag when it should be localized; the ore output and host tags remain independent.

The spawn platform is shared at the ocean surface. A persisted marker and SavedData state make it idempotent. Its chest supplies saplings, soil, seed crops, bread, stone, cobblestone, kelp, sand, lava and water. Kelp is placed as a renewable seafloor resource. NauTec's salt-water collection is enabled in the Maginautica config; true ocean biomes carry NauTec integration tags and its bacteria-obtaining map accepts sand and podzol in this marine biome palette. Recipe files provide renewable sand/gravel, prismarine shards, salt and a starting grafting-tool route. The platform chest's cobblestone and the renewable tree route provide material for renewable iron nuggets. This prototype does not finish a complete endgame or cross-dimension recipe rebalance.

The Overworld structure allowlist contains the custom buried salvage rooms plus NauTec crystal geodes, research outposts and seabed ruins, whose loot supplies progression components. Vanilla strongholds and other continental structure sets remain suppressed by the generator's structure-set filter. The NauTec underwater gateways are not enabled; Nether and End still generate normally, but the Overworld does not yet supply an adapted End portal structure, so a complete progression replacement remains unfinished. Ordinary ores are disabled in Oceanblock. Special resource features remain unavailable unless deliberately added to the profile tags. Exploration ore patches choose blocks from `magitema_ocean:exploration_ores` and replace hosts from `magitema_ocean:exploration_ore_hosts`. The ore tag optionally imports the common `c:ores` tag, so convention-tagged modded ores participate automatically; `magitema_ocean:exploration_ore_exclusions` omits dimension-specific entries, and datapacks can extend all three tags. Entries are currently selected uniformly, so adding many block variants changes their relative frequency. Exploration placed features and structures are separately opt-in through the profile's worldgen tags. Only add third-party features after checking their height placement and ocean suitability; the generator intentionally does not run every mod's default biome decoration.

## Development notes

Terrain uses original seed-wired broad geography, ridge, channel and local-detail noise. The channel field uses a coarser first octave (`-11`) so deep trenches form broader connected regions; a 24,576-block grid at 128-block spacing retained about 11.8–12.5% samples below Y −485 across two prior audits, and the largest sampled connected region grew from 14 to 248–264 cells compared with the finer baseline. The marine classifier reads the shared analytical floor and compares four nearby floor samples for local slope and bowl shape, so terrain, biome regions and substrate rules use one geography source. Buried salvage samples that same seed-wired `RandomState` floor, not the unseeded settings template. Its biome allowlist includes both cave biomes because a room placed 48 blocks under the seabed usually starts inside a cave biome. The cave density uses local floor elevation and a neighboring-floor safety envelope. Aquifers are disabled only for this custom preset; its scoped fluid picker leaves continuous ocean source water above the floor, air above the surface and dry underground cavities below a protected cover. Vanilla configured carvers are disabled only for the custom generator. No neighboring chunks are synchronously loaded from the density sampler.

The profile lock captures relevant effective worldgen, tag, loot, recipe and NauTec biome-injector data. Old chunks retain old generation as usual; create another new world after changing any generator resource. Never test this by converting a Magitema save.

NauTec 2.0.19 ships four Lithostitched biome injectors under `data/nautec/lithostitched/biome_injector`; they target `minecraft:overworld` and replace climate-selected ocean cells with NauTec biomes. The selected presets instead use the namespaced `magitema_ocean:deep_overworld` dimension type. In the dedicated-server smoke log, Biolith reports that it skips `minecraft:overworld` because of that custom type. This is evidence about Biolith's behavior, not proof that every Lithostitched injection path is inert; direct verification of NauTec/Lithostitched replacement against `MarineBiomes` remains open.

## Runtime terrain and generation measurements (2026-10-23)

Direct `OCEAN_FLOOR_WG` audits sampled a 24,576 × 24,576-block square at 128-block spacing (37,249 points) for Oceanblock seeds `6310242026`, `8675309`, and `3141592653`. All three had zero above-water samples. Across the seeds, measured water depth ranged from 82 to 606 blocks; the median was 320–321 blocks, the 95th percentile was 552–561 blocks, and 15.7–17.3% of samples were at least 400 blocks deep. This confirms the intended shelves, basins and broad trenches at sampled map scale. The raw reports and seafloor previews live in `../tests/maginautica-oceanblock-direct-floor-audit-*.json` and `*.png`.

Cold full-chunk requests used the same 16 remote chunk coordinates and seed `6310242030` for Exploration and an ordinary `minecraft:normal` world, with the same Maginautica mod stack. Exploration averaged 681 ms per generated chunk (615.5 ms median, 1,002 ms maximum); the normal-world baseline averaged 2,997 ms (2,395 ms median, 6,550 ms maximum). This sample is about 4.4× faster on average. It measures chunk generation only; the separate block verification scan is excluded. Oceanblock also generated 16/16 fresh chunks for seed `3141592653`, averaging 755 ms with a 1,320 ms maximum. A separate saved 4×4 abyssal patch on seed `3141592718` showed matching floor-height delta profiles across chunk edges and within chunks (median 1, p95 2, max 3 blocks); this checks one local area only.

Runtime scans found all enabled marine features in every sampled chunk: tall seagrass, Nautec abyssal coral, deep kelp and prismarine fronds. Oceanblock produced zero `_ore` blocks across 16 sampled chunks. Exploration produced 58–70 ore blocks per chunk, within its 72-attempt ceiling, including Create zinc, Magitech fluorite/tourmaline/zinc and ZPS lithium in stone/deepslate hosts. Ore blocks and compatible host blocks remain data-tag extensible; placed features are separately allowlisted by profile so unsuitable third-party decoration does not run by default.

The dry-cave fluid audit sampled 16 adjacent full chunks and found 86,528 air blocks below the seabed with no water or lava, including after a 60-second tick and a world close/reopen. The after-reload scan again found zero below-floor fluids in all 16 chunks. The expanded biome pass loaded the updated preset in fresh worlds and sampled 37,249 positions over 24,576 × 24,576 blocks. All ten marine IDs appeared. Hadal trench floors ranged from Y −540 to −486; abyssal basins −485 to −386; basalt ridges −335 to −156; volcanic flanks −385 to −336; seamount slopes and rocky seabed −385 to −156; sand shelves −155 to −19; kelp groves −155 to −19; coral gardens −82 to −19; sheltered lagoons −120 to −23. Their counts ranged from 94 lagoons and 359 volcanic slopes to 7,951 seamount and 7,792 rocky-floor samples. Ten full-chunk samples confirmed sand on the shelf/reef/lagoon floors and basalt on ridge/flank floors, with gravel on abyssal, hadal, rocky and seamount floors. A 64-chunk reef patch contained vanilla coral blocks/fans and 265 sea-pickle blocks; the kelp-grove sample contained 14 kelp starts and 159 kelp-plant blocks. Hadal/ridge/flank samples also contained NauTec vent blocks, magma and tubeworms. The reports are kept in the wrapper's `../tests/maginautica-ten-biome-samples-cached-3141592690.json`, `../tests/maginautica-biome-material-feature-chunks-final-3141592690.json`, `../tests/maginautica-biome-reload-scan-3141592690.json` and `../tests/maginautica-coral-reef-feature-density-3141592690.json`.

These are bounded client-world samples, not proof across every seed. Two dedicated-server seeds now produce buried salvage structures using the seed-wired floor; a same-seed test confirmed the biome allowlist must include cave biomes, and the corrected structure/chest survives save and restart. Cold `/locate structure` timing varies with vanilla structure-region reads, so it is not used as a chunk-generation metric. Those structure checks used the rebuilt artifact in the isolated dev-server, not the Prism profile. The project control-root `AGENTS.md` currently prohibits deployment to Prism or Crafty, so Maginautica still has its previous JAR until that restriction is explicitly changed. The complete NauTec survival loop and direct Lithostitched injector effect remain unverified. The same-seed chunk comparison is a useful pack-level performance baseline, not a hardware-independent benchmark. The direct terrain audit peaked at about 23.3 GB process working set with the full Maginautica client stack; this includes client, mod and audit memory and is not a server-only heap measurement.

The y-independent analytical floor is wrapped in `minecraft:cache_2d` in both presets, and the terrain density function preserves the actual `NoiseChunk` context so that cache is effective during vertical sampling. Two fresh dedicated-server trials over the same 16 remote chunks averaged 640 ms/chunk after this change, compared with 703 ms/chunk for the immediately preceding cache variant and 678 ms/chunk for the earlier baseline. All 16 chunks reached full status, and biome palettes plus four saved heightmaps matched between the two floor-cache trial worlds. This small sample suggests a useful improvement but is not a hardware-independent performance guarantee. Run records are in the wrapper's `../tests/maginautica-oceanblock-floor-cache-*.json`.

The Exploration ore picker imports the optional `c:ores` block tag, then removes Nether-only ores and Create ReAutomated's ore-node deposits through a separate exclusion tag. A fresh 16-chunk dedicated-server audit generated 973 eligible ore blocks from 74 block IDs across 16 mod namespaces; no excluded block appeared. Convention-tagged ores therefore participate without source edits, while ores omitted from `c:ores` can still be added through the project tag. The tag currently selects block IDs uniformly, so modded distribution weights remain a tuning choice.
